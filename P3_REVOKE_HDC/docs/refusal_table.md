# Outcome and Refusal Table - REVOKE-HDC (Week 1 Frozen)

This table defines all 11 possible outcomes generated by the REVOKE-HDC controller, their numerical codes, impact on prototype memory, and project-specific trigger conditions.

| Code | Outcome Name | Prototype Mutated? | Journal Mutated? | Project-Specific Trigger Condition |
|:---:|---|:---:|:---:|---|
| **0** | `accepted` | **Yes** | **Yes** | All structural, CRC-16, alphabet, expected-bit, agreement/margin, monotonic sequence, journal capacity, and stored-bit checks pass. Journal record is durable in BRAM ring and marked `ACTIVE` in index table strictly before prototype bits commit. |
| **1** | `quarantined` | **No** | **No** | Packet is structurally valid, but the multi-modal agreement check ($h_A == h_B == \text{class\_id}$) fails, or one or both confidence margins fall below threshold ($m_A < \theta_A$ or $m_B < \theta_B$). Candidate update is held outside active journal and never applied. |
| **2** | `refused_capacity` | **No** | **No** | Required record bytes ($J_{\text{req}} = 16 + 2F$) exceed available free contiguous bytes in the BRAM ring ($J_{\text{req}} > J_{\text{free}}$), or no free slot exists in the Record Index Table ($N = 1024$). |
| **3** | `refused_checksum` | **No** | **No** | The recomputed CRC-16/CCITT-FALSE over header and payload entries does not match the 16-bit `checksum` field in the packet header. |
| **4** | `refused_residue` | **No** | **No** | An entry's signed `pre_update_residue` falls outside $[-8, +7]$, or `update_contribution` falls outside the encodable $[-8, +7]$ alphabet (including conceptual $+8$ which overflows signed 4-bit representation). |
| **5** | `refused_stale` | **No** | **No** | For at least one entry in the packet, the recomputed pre-update bit ($\text{sign\_threshold}(pre\_residue)$) does not match the currently stored prototype bit in memory. |
| **6** | `refused_duplicate` | **No** | **No** | A dimension index occurs more than once within the same candidate update packet. Partial mutation is forbidden. |
| **7** | `refused_ordering` | **No** | **No** | At admission: packet sequence count does not match the next expected monotonic sequence for that class. At restoration: the requested $(\text{class\_id}, \text{update\_id})$ record is not the current `ACTIVE` head of the class chain (attempting out-of-order restoration). |
| **8** | `refused_bit_state` | **No** | **No** | At admission: sender's `expected_old_bit` or `expected_new_bit` disagrees with recomputed threshold math, or format/reserved bits are non-zero. At restoration: the currently stored prototype bit differs from the record's expected post-update bit. |
| **9** | `restored` | **Yes** *(reverted)* | **Yes** *(retired)* | Restoration request for the current active class head passes all bit-state checks. Old bits are reconstructed from retained residues as $\text{sign\_threshold}(residue)$, combined per 64-bit word, applied to prototype memory, and the record slot transitions `ACTIVE -> RESTORING -> RETIRED`. |
| **10** | `already_retired` | **No** | **No** | A restoration request targets an `update_id` whose record is already in the `RETIRED` state. Prevents repeat restorations from double-flipping prototype bits. |

---

## Invariant Post-Conditions

1. For all refusal codes ($2..8$), `quarantined` ($1$), and `already_retired` ($10$):
   - **Zero prototype bits are modified**.
   - **Journal `free_bytes` and head pointers are unchanged**.
   - Exactly one counter (`REFUSED_COUNTER`) is incremented.
2. For `accepted` ($0$):
   - Exactly one journal record is persisted.
   - `UPDATE_COUNTER` is incremented by 1.
3. For `restored` ($9$):
   - The head record is retired.
   - `RESTORE_COUNTER` is incremented by 1.
